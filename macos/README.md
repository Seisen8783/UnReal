# A Console macOS 控制台

通过 USB 连接自己的测试 iPhone，在 Mac 上预览和回放 GPX、KMZ 或 KML。控制台可以定位到起点、拖动时间条跳转、从起点重播，并在暂停时保持当前位置。

## 下载与安装

安装包已内置 Python 和设备桥接依赖，首次启动和刷新 USB 设备可离线完成。新版 DMG 和安装步骤见[仓库首页](../README.md)。

定位模拟会优先使用设备上已启用的开发者服务。已有相容的 iOS 开发者镜像时，可以将 `A_CONSOLE_DDI_RESTORE_DIR` 指向包含 `BuildManifest.plist` 和对应载荷的 `Restore` 目录。Mac 也会检查 Xcode 在系统及用户资料库中准备的镜像。便携版 uv 位于应用包内。应用包不含 Apple 镜像文件，设备如需重新个性化授权仍可能需要联网。

## 回放轨迹

1. 用 USB 数据线连接 iPhone，解锁并信任 Mac。iPhone 需要运行 iOS 17 或更新版本并开启[开发者模式](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。如果设置里没有该开关，可先在 Xcode 的设备窗口确认配对，再回到手机检查。
2. 在控制台刷新设备列表并选中 iPhone。侧边栏「轨迹来源」选**默认路径**（内置的校园跑走廊，启动时自动载入）或**本地导入**（唤起文件选择器）。也可以把文件直接拖进预览区。 [20 秒测试轨迹](Tests/Fixtures/sample.gpx)
3. 点击「接管定位权限」可先在手机上核对位置，再点「开始回放」。播放中拖动时间条可跳到最接近的采样点。
4. 点击「暂停」会保持当前位置。点「继续回放」从暂停点继续。**回放自然结束后设备位置会退回轨迹起点并保持**，要恢复真实定位点「重置位置」。若拔线后出现「待恢复」，重新连接同一台设备，再点「重置位置」。

## 校园跑：先撞库，再回放

「校园跑」这类小程序的判定链有严格的顺序，顺序错了坐标再准也没用：

1. **先到操场边的打卡桩刷脸（撞库）**。成绩是打卡桩算的，不是手机算的；
   没有完成撞库，之后刷出来的数据服务端不认。
2. **再开始回放**。撞库完成后回到控制台：「接管定位权限」→「开始回放」。
3. **全程待在操场上**。手机上报的位置一旦离开操场围栏，小程序会标「非校园区域」。
   回放期间不要把手机带出操场。
4. **人走多快都行，模拟可以更快**。真实步速慢不影响刷桩，但控制台的「配速」可以调快
   （最快 1'00"/公里），模拟轨迹在更短时间内跑完。里程按打卡桩之间的标定距离累计，
   跑得快慢不改变距离。

推荐设置：上报口径「原样」、标定偏移 **东 -17.2 m / 北 -11.5 m**、配速 **8'00"~12'00"**（按你实际走路的速度填）、「公里数」按需要填。
配速填太快（< 5'00"/公里 ≈ 12 km/h）会让小程序显示超出人类极限的配速，比「非校园区域」更容易触发风控；
里程按打卡桩之间的标定距离累计，所以桩给的是真实速度——配速填成真实步速，两条证据链才自洽。

**侧栏的「校园跑模式」按钮一键套用这些设置**，套用后主区会出现流程清单（点一下勾掉已完成的步骤）：
内置轨迹、偏移 东 -17.2 / 北 -11.5、口径「原样」、配速 8'00"、目标 1.50 km。
站在操场边刷脸时不用现调参数。

> 为什么要这组偏移：内置轨迹是照着「理想跑道」画的，北侧贴着围栏边（只剩 0.4 m），
> 东侧也只差 4.4 m，而围栏本身是从截图反推的、残差有 ±7 m —— 等于压线过线。
> 这组偏移把整条轨迹挪到**实测可达区**的中心：跑道形状和每圈长度（906 m）完全不变，
> 围栏余量变成 12.0 m，同时 244 个原本超出实测可达区的点也全部回到区内。

回放前先做一次围栏预检，确认整条轨迹都在操场围栏里、并且离边界留有余量：

```bash
python3 tools/fence_check.py core/assets/campus.geojson
python3 tools/fence_check.py core/assets/campus.geojson --calibration -17.2,-11.5   # 加上偏移后复验
```

余量不足时，工具会给出三种改法：平移到实测可达区中心、平移到围栏中心、把轨迹向内收缩若干米。

## 配速和圈数

- 带完整时间戳的 GPX 或 KML `gx:Track` 按记录时间回放。只有坐标的 KML 或 KMZ 按输入配速生成时间，默认 **7:29 分/公里**。
- 从多圈轨迹识别出闭合路线后，可以启用「使用单圈中线」并填写总圈数。右上角显示当前圈和总圈数。
- **长度计量二选一**：一个下拉框选「总圈数 / 公里数」，右侧填对应数值。
  - 切到「公里数」时，若输入框还是空的，会按当前总长度自动预填（如 `0.45`），免得面对空框。
  - 切换轨迹后，若公里数是自动预填的（没手动改过），会按新轨迹重算。
- 右上角除圈数外还会显示米数进度 `111.2m/400.0m`。
- 暂停时可调整无原始时间戳轨迹的配速和单圈中线的总圈数。有效输入会自动同步，已回放进度与暂停位置保留。总圈数至少要等于当前圈。

## 坐标基准与标定偏移

设备只接受 WGS-84。导入的轨迹若来自腾讯/高德/百度地图，基准就不是 WGS-84，需要在「坐标基准」里选对，否则整条轨迹会平移数百米。「标定偏移」用于基准相同但原点不同的情况，按米（东/北）平移。

**内置默认轨迹的基准固定为 WGS-84**（它与 `core/assets/campus.geojson` 逐点一致，后者已声明为 WGS-84），不随「坐标基准」的选择改变；只有本地导入的轨迹才按你选的基准解读。

归一化与偏移的顺序不能反：基准转换是非线性变换，必须先做；标定偏移是米制平移，必须在经纬度空间做。单圈中线也在归一化之后才拟合，否则会与点集错开一个基准。

**内置默认轨迹的基准固定为 WGS-84**，不随「坐标基准」选择改变——选本地导入后才能改基准。
该文件与 `core/assets/campus.geojson` 逐点一致，而后者在 README 中声明为 WGS-84；
若按 GCJ-02 解读会整体平移约 525 米。

### 上报口径

「校园跑」这类小程序用 `wx.startLocationUpdateBackground` 取定位（未指定 `type`，微信默认 **gcj02**），
把设备交付的 WGS-84 转成 GCJ-02 后**原样上报**给服务端做围栏判定。

服务端围栏若是 WGS-84（从 GPS/测绘数据导入的常见做法），两者就差一个基准偏移量——滨州一带约 525 米。
结果就是：明明在操场上跑，判定却是「非校园区域」，里程显示 `--km`、配速 `0'00"`（服务端未采信这段），
但时长有值（客户端自己记的）。

「上报口径」选**回退一个基准**，就是预先做一次 GCJ-02 反解，让微信转回来正好等于文件原值。
默认口径为「原样」；应根据实际接收方的坐标处理方式选择。

> **校园跑这一例：必须用「原样」。** 服务端围栏（`core/assets/campus-fence.json`）与小程序上报同基准，
> 都是 GCJ-02。选「回退一个基准」会让上报值整体偏一个基准（滨州一带约 525 米），
> 整条轨迹都落在围栏外，必然被判「非校园区域」。`tools/fence_check.py` 会把两种口径都算一遍。

判断基准与计算偏移：

```bash
python3 tools/coordinate_probe.py 轨迹.kmz --probe 37.387769,117.982438   # 用已知地物判读
python3 tools/coordinate_probe.py 轨迹.kmz --target 37.387769,117.982438  # 算所需偏移
python3 tools/fence_check.py 轨迹.kmz --calibration -17,-3                # 围栏预检（默认校园围栏）
```

iOS 的定位模拟用于开发测试。其他 App 是否显示模拟坐标、如何计算里程或配速，取决于各自的处理逻辑。

## 从源码构建

在仓库根目录运行以下命令。也可以用 Xcode 打开 [Package.swift](Package.swift)。

```bash
./macos/build-app.sh
swift test --package-path macos --disable-sandbox
"macos/build/A Console.app/Contents/Resources/python/bin/python3" -I -B -m unittest discover -s macos/Tests/Python -v
```

受限终端里 SwiftPM 自带的沙箱会因 `sandbox_apply` 失败，需要加 `--disable-sandbox`；
`build-app.sh` 检测到会自动退回无沙箱模式重试。

构建产物位于 `macos/build/A Console.app`。

## 版本号

版本号存在仓库根的 `VERSION` 文件里。**每次构建自动 +0.0.01 并写回**，
构建出来的包用的是递增前的版本号，所以界面上显示的版本与安装包始终一致。

界面左上角产品名右侧会显示当前版本。要指定版本，改 `VERSION` 文件即可。

图标由 `tools/icon/make_icon.swift` 生成（白底 + 蓝色圆 + 深色导航箭头），构建时自动合成 `.icns` 打进包里。

接管后回放结束会返回起点；点击「重置位置」发送恢复真实定位的请求。连接中断、设备重启或系统终止可能使模拟定位失效，重新连接后可再次接管。回放时显示预计完成时间，暂停期间不显示具体完成时间。
